## 第 1 章 难度校准(与公开集对齐)

目标:回答"我说这题是 L3,凭什么"。做法是**不自证**——难度标签不由生成模型自评,而是由"合成题与公开锚点题在同一组基线模型上的相对表现"外部锚定。

### 1.1 锚点法

#### 1.1.1 基线模型池(baseline pool)

| 项 | 设定 | 依据 |
|---|---|---|
| 模型数 | **6 个**,分三层:强 2 / 中 2 / 弱 2 | [经验] 少于 4 个时档间通过率阶梯不稳;多于 8 个边际收益低而成本线性涨 |
| 分层定义 | 强=当代第一梯队;中=落后约一代或中等尺寸;弱=小尺寸开源(7B~14B 级) | [经验] 需要弱模型把 L1 的天花板压出区分 |
| 同源约束 | 基线池 **不得与被测组合同源**,也不得与合成流水线的生成/验证模型同源;若无法完全避开,同源模型的分数只作参考、不进入映射拟合 | 与流水线既有"三方不同源"约束一致 |
| 采样 | 每题 **k=5** 次,temperature=统一固定值(建议 0.7),取 pass rate(非 pass@5) | [经验] k=5 是题级通过率方差与成本的常用折中;见 1.2.2 的区间推导 |
| 提示词 | 锚点题与合成题使用**同一套** system prompt / few-shot 设置;锚点题不得使用其官方特调 prompt | 否则映射被 prompt 差异污染 |

#### 1.1.2 各门类锚点集建议

选锚点的三条硬标准:**(a) 有官方难度标签或可代理难度的字段;(b) 有可判定的 gold;(c) 有发布时间可用于判断污染。**

| 门类 | 锚点集 | 可用的难度字段 | 备注 |
|---|---|---|---|
| G1 知识问答 | **GPQA Diamond** + MMLU-Pro;中文加 C-Eval / CMMLU 的学段分层 | GPQA Diamond 本身即"专家可答、非专家+检索难答"的高难子集;MMLU-Pro 按学科 | GPQA Diamond 仅 198 题,只够锚 L3 端;L1/L2 端靠 MMLU-Pro |
| G2 信息检索 | BEIR 子集 / BRIGHT(推理型检索) | 无官方难度档 → 用**基线 nDCG@10 分位**自造三档 | [需标定] 分位切点 |
| G3 内容理解 | **LongBench v2** | 官方 easy(192)/hard(311),另有 short(<32k)/medium(32k–128k)/long(>128k) 长度档 [引用] | 难度与长度双维度,映射时长度作协变量 |
| G4 文案撰写 | Arena-Hard-Auto / WritingBench | 无客观难度档 | **不做通过率锚定**,见 1.1.4 |
| G5 方案设计 | Arena-Hard-Auto 的 planning 类子集 | 无 | 同上 |
| G6 数据分析 | **DABStep**(Adyen×HF,含 hard 子集,多步表格推理)[引用];补 TableBench | easy / hard 两档 | hard 档锚 L3,easy 锚 L1–L2 |
| G7 代码与SQL | **BIRD**(simple/moderate/challenging,按 JOIN/GROUP BY/子查询等结构复杂度标注)[引用] 锚 SQL;**LiveCodeBench**(平台 easy/medium/hard + 精确 release date)[引用] 锚代码 | 三档齐全 | LiveCodeBench 只取**晚于所有基线模型训练截止**的分片,避免污染 |
| G8 故障诊断 | **SWE-bench Verified**(人工标注修复耗时 <15min / 15min–1h / 1h–4h / >4h)[引用] | 耗时档作难度代理 | 最接近"诊断+定位+修复"的公开代理任务;域不完全匹配,见 1.1.5 |
| G9 工具与系统操作 | **BFCL v3**(Base / Miss Func / Miss Param / Long Context 四类多轮)[引用];τ-bench(retail/airline) | 无显式难度档 → 用**类别 + 所需调用步数**作代理 | 步数分档需实测 [需标定] |
| G10 工作沟通建议 | 无合适锚点 | — | 不做通过率锚定,见 1.1.4 |
| S 安全合规 | 不参与难度校准 | — | S 走"风险等级 × 攻击强度"独立标尺,与 L1/L2/L3 不通用 |

#### 1.1.3 映射方法(通过率 → 锚点尺度)

1. 同一批次内混跑锚点题 $A$ 与合成题 $C$(同 prompt、同 k、同 6 模型)。
2. 对每题算基线池平均通过率 $\bar p = \frac{1}{mk}\sum_{j,t} \mathbb{1}[\text{correct}]$,$m=6,k=5$。
3. 在锚点题上拟合 **单调映射** $f: \bar p \mapsto \text{difficulty}$。推荐 **isotonic regression**(保序,不假设函数形式);样本少时退化为**分位对齐**:取锚点 easy/medium/hard 三档 $\bar p$ 的经验分布,用其 33/67 分位作为切点。
4. 把 $f$ 套到合成题的 $\bar p$ 上,得**校准后难度**;与生成时声明的难度标签比对。
5. **不一致处置**:声明 L3 但映射为 L1 → 标签以映射为准并回写;不一致率作为生成 prompt 的质量信号。单批不一致率 > **30%** [需标定,建议首轮实测后收紧] 则该批生成配置整体返工,而非逐题改标。

**锚点题数量**:每门类每档 **≥ 30 题** [经验],用于拟合切点;低于 30 时切点置信区间过宽,应合并相邻门类共用切点。

#### 1.1.4 rubric-only 门类(G4/G5/G10)怎么办

这三类没有确定性 checker,通过率本身就是 judge 分数的二值化,锚点法**部分失效**。诚实做法:

- 用 **rubric 满足率** 代替通过率:定义每题 rubric 条目数 $R$,得分 = 满足条目数 / $R$,阈值 0.8 视为"通过"[需标定]。
- 难度定义改为 **rubric 条目数 + 约束冲突数**:L1 ≤3 条无冲突约束;L2 4–7 条含 1 个软冲突;L3 ≥8 条含 ≥2 个硬约束/受众冲突。这是**结构定义而非实测定义**,必须在文档里明说它与 G1/G6/G7 的 L3 不等价。
- 仍然要跑 1.3 的区分度检验:rubric 题若所有被测组合得分几乎相同,同样无信息量,照样淘汰。

#### 1.1.5 锚点法的已知失效点(不遮掩)

| 失效点 | 后果 | 缓解 |
|---|---|---|
| 公开锚点已被基线模型训练污染 | 锚点 $\bar p$ 虚高 → 合成题被系统性标难 | 只用发布时间晚于模型截止的分片(LiveCodeBench 天然支持);对无时间戳的集,用 canary 对照检测异常高分 |
| 锚点域 ≠ 合成题域(G8 尤其:SWE-bench 是代码仓库,业务故障诊断不是) | 映射跨域外推 | G8 的映射结果只作**排序参考**,档位切点必须叠加人工复核 [需标定] |
| G2/G9 无官方难度档,靠自造分位 | 切点是循环定义(用基线定难度,又用难度评基线) | 自造分位必须由**独立于被测的**基线池产生,且切点冻结后至少一个周期不动 |

### 1.2 通过率反标

#### 1.2.1 目标区间

| 档 | 基线池平均通过率 $\bar p$ | 依据 |
|---|---|---|
| L1 | **> 0.80** | [经验] 留给"几乎所有可用模型都该做对"的底线题;高于 0.95 的题区分度必然塌陷(见 1.3),需限额 |
| L2 | **0.40 – 0.80** | [引用/经典测验理论] 二值题在 $p\approx0.5$ 附近方差 $p(1-p)$ 最大、Fisher 信息最高,区分力最强;L2 占配比 50% 正是为了把信息量堆在这里 |
| L3 | **< 0.40** | [经验] 低于 0.05 的题接近全错,信息量同样趋零 → 设下界 **0.05**,低于此转入 frontier 池(不计分,只做 headroom 观测) |

配比 3:5:2 与区间是一致的:信息量最大的 L2 拿到最大权重。

#### 1.2.2 需要多少样本才统计可靠

用 Wilson 区间半宽估计。$n$ 为独立二值观测数,最坏情况 $p=0.5$,95% 置信:

**题级**(一道题的 $\bar p$ 有多准):$n = m \times k$。

| $m\times k$ | 半宽(p=0.5,95%) | 能分辨什么 |
|---|---|---|
| 6×5 = 30 | ≈ **±0.17** | 只够区分 L1/L2/L3 三大档,**不够**做档内细分 |
| 6×10 = 60 | ≈ ±0.12 | 勉强能判"是否越界" |
| 10×10 = 100 | ≈ ±0.10 | 可做档内排序 |

结论:**题级通过率天生粗**,$6\times5=30$ 时 ±0.17 已经跨过 L2 的一小半。所以 (a) 题级只做三分档,不排细序;(b) 越界判定要求**连续两个批次**都越界才动标签;(c) 注意 $m\times k$ 里同一模型的 k 次采样**不独立**,存在设计效应,真实半宽比上表更宽 [需标定:实测同模型内 ICC 后修正]。

**档级**(某档整体均值有多准):$N$ = 该档题数。取 $p=0.5$、半宽目标:

| 档内题数 $N$ | 半宽 | 用途 |
|---|---|---|
| 100 | ±0.098 | 太宽,不足以判漂移 |
| 200 | ±0.069 | 最低可用 [经验] |
| **384** | **±0.050** | 推荐;$n = z^2p(1-p)/w^2 = 1.96^2\times0.25/0.05^2 \approx 384$ |
| 1000 | ±0.031 | 用于季度漂移判定 |

**建议最小规模**:每门类每档 ≥ 200 题(11 门类 × 3 档 ≈ 6600 题),其中 L2 按 3:5:2 自然更多。低于此的门类(如 S 或冷门子类)必须在报告里标注"档级结论置信区间过宽,仅供参考",不得当结论用。

**split 交互**:dev 30% / test 60% / canary 10%。canary 只占 10%,若总量 6600 则 canary ≈ 660 题、分到单门类单档仅 20 题(半宽 ±0.22)——**canary 不足以做档级统计**,它的用途是污染检测(test 与 canary 分差显著 → 疑似 test 泄漏),不是难度结论。

### 1.3 区分度(本章重点)

核心命题(借 IRT):**所有被测组合都答对、或都答错的题,对区分模型能力的信息量为零**,无论它"看起来"多难。一个 benchmark 的实际价值,约等于其高区分度题的数量,而不是总题数。

#### 1.3.1 计算方式

设有 $M$ 个被测组合(respondent),题 $i$ 上组合 $j$ 的二值得分 $X_{ij}\in\{0,1\}$(rubric 题取满足率二值化,或直接用连续分做 Pearson),组合 $j$ 的总分 $T_j$。

**(a) 校正点二列相关(主指标)**

$$r_{pb}^{(i)} = \frac{\bar T_{1} - \bar T_{0}}{s_T} \sqrt{\frac{p_i(1-p_i)}{1}}\quad\text{(用 corrected item-total:} T_j \text{中扣除本题得分)}$$

- $\bar T_1 / \bar T_0$:答对/答错本题的组合的平均总分;$s_T$:总分标准差;$p_i$:本题通过率。
- **必须用 corrected 版本**(总分里扣掉本题),否则题目与自身相关,$M$ 小时虚高严重。
- rubric 连续分直接用 Pearson $r(X_{\cdot i}, T_{-i})$。

**(b) 高低分组差异 D(辅助,直观且对小 $M$ 稳健)**

按总分排序,取上 27% 与下 27%(Kelley 27% 规则 [引用,经典测验理论]):$D_i = p_i^{\text{upper}} - p_i^{\text{lower}}$。

**(c) 方差与"死题"判定(前置筛)**

$\mathrm{Var}_i = p_i(1-p_i)$。$p_i \in \{0,1\}$ 时 $r_{pb}$ 未定义 → 直接进死题流程(1.3.3)。

**(d) IRT 2PL 判别参数 $a$(可选,不作硬门槛)**

2PL 稳定拟合通常需要**数百个 respondent**;而我们现实中 $M$ 往往只有 10–30 个模型组合。因此 **$a$ 参数在本方案中只作辅助诊断,不用于淘汰** [需标定:待 $M\ge 100$ 的伪被测池建成后再评估]。

**(e) 把 $M$ 做大:伪被测池(pseudo-respondent pool)**

$M$ 太小是本节最大的工程障碍。扩充办法:

| 手法 | 产出的 respondent 数 | 注意 |
|---|---|---|
| 真实被测组合 | 10–30 | 基数 |
| × 温度/采样种子(3 档) | ×3 | 同模型内高度相关,计入设计效应 |
| × prompt 变体(zero-shot / CoT / few-shot) | ×3 | 变体间差异比温度大,更有效 |
| + 独立基线池(1.1.1 的 6 个) | +6 | 与被测不同源,提升外部效度 |
| + 故意弱化的对照(截断上下文/去 CoT) | +2~4 | 专门用来压出 L1 端区分 |

目标 **$M_{\text{eff}} \ge 40$** [经验] 再计算 $r_{pb}$;不足 40 时只报 $D$ 与方差,不报 $r_{pb}$。

#### 1.3.2 阈值与处置

| $r_{pb}$ | 分级 | 处置 | 依据 |
|---|---|---|---|
| ≥ 0.40 | 优 | 保留,优先进 test | [引用] Ebel 分级 |
| 0.30 – 0.39 | 良 | 保留 | [引用] |
| 0.20 – 0.29 | 可 | 保留但标记,下一周期复查 | [引用] |
| 0.10 – 0.19 | 弱 | 退回 dev,不进 test 计分 | [经验] |
| < 0.10(非负) | 无信息 | **淘汰**或改写 | [引用] $\ge 0.20$ 是经典测验理论通用下限,0.10 是我们放宽后的硬底 |
| **< 0**(负区分度) | 异常 | **强制人工复核 gold**——负相关的最常见成因是答案键错、多解未记、checker 写反 | [经验] 这是查 gold bug 最高效的单一信号 |

辅助门槛:$D \ge 0.20$ [经验];$0.05 \le p_i \le 0.95$(方差下限 0.0475)。

**淘汰配额**:单个重标周期内,单门类淘汰率 **≤ 25%** [经验]。超过说明问题在生成配置而非个别题,应返工生成再重跑,而不是继续砍题——无限制淘汰会把 benchmark 过拟合到当前这代模型上。

#### 1.3.3 死题(零方差)必须分两类处理

| 情形 | 可能成因 | 判别动作 | 处置 |
|---|---|---|---|
| **全对** $p=1$ | 题太简单;或答案可从 prompt 猜到(gold 泄漏,见第 4 章) | 检查 prompt 是否含答案;检查是否为常识题 | 若确属简单 → 降为 L1 并计入 L1 限额;L1 中 $p=1$ 的题占比上限 **20%** [需标定] |
| **全错** $p=0$ | (i) 真前沿题;(ii) **gold 错**;(iii) checker/rubric 有 bug;(iv) 题面不可解(缺信息) | **100% 人工复核**,不得跳过 | (i) → frontier 池,不计分只观测,配额 ≤ 总题量 5% [经验];(ii)(iii)(iv) → 修或删 |

**全错题必须逐题人工过**——这是本方案里唯一不允许自动化替代的环节。经验上合成集里的 $p=0$ 题,gold 错的比例远高于直觉 [需标定:首轮统计实际比例并回填]。

#### 1.3.4 集合级指标

除逐题外,每批次报三个集合级数:

| 指标 | 定义 | 目标 | 依据 |
|---|---|---|---|
| 有效题率 | $r_{pb}\ge0.20$ 的题占比 | **≥ 70%** | [经验/需标定] |
| 去题增益 | 去掉题 $i$ 后 Cronbach $\alpha$ 上升的题数占比 | ≤ 10% | [经验] 上升说明该题在拉低一致性 |
| 排名稳定性 | bootstrap 重采样题目 1000 次,被测组合排名的 Kendall $\tau$ 中位数 | **≥ 0.90** | [经验] 低于 0.9 说明题量不足以稳定排名,应加题而非调阈值 |

排名稳定性是最贴近"benchmark 有没有用"的单一指标:如果换一批题排名就变,区分度再好也没意义。

### 1.4 难度漂移与周期性重标

#### 1.4.1 触发条件(满足任一即触发)

| # | 条件 | 阈值 | 依据 |
|---|---|---|---|
| T1 | L3 档均通过率越上界 | $\bar p_{L3} > 0.40$ 且连续 **2** 个批次 | 与 1.2.1 区间一致 |
| T2 | L3 中"已塌陷"题占比 | $p_i > 0.80$ 的题 > **20%** | [经验] |
| T3 | L1 中"倒挂"题占比 | $p_i < 0.50$ 的题 > **10%** | [经验] 通常指向 gold 退化或 checker 漂移,而非模型变弱 |
| T4 | 有新 SOTA 进入基线池 | 任一新模型使档均通过率变动 > **0.10** | [经验] |
| T5 | 定期 | 距上次重标 ≥ **2 个季度** | [经验] 按当前模型迭代节奏 |
| T6 | 污染信号 | test 与 canary 同档通过率差 > **0.15** 且显著 | [需标定:先实测正常波动幅度] |

#### 1.4.2 重标做法

1. **冻结 gold,只改标签**。重标是 relabel,不是重写题目;重写会让历史分数不可比。
2. **标签版本化**:每题保留 `difficulty@v1/v2/...` 与 `calibrated_at`、`baseline_pool_id`。任何对外报分必须注明用的哪个版本。
3. **锚点集同步换代**:老锚点被污染后一并替换(LiveCodeBench 换晚期分片、GPQA 换新题)。锚点换了,切点必须重拟合,不能沿用。
4. **塌陷题降档而非删除**:L3→L2、L2→L1;删除会破坏配比且丢历史。降档后按 3:5:2 从 frontier 池补新 L3。
5. **保留桥接集**:每次重标保留 **≥ 15%** 的题标签不变作为桥接锚 [经验],用于把新旧两版分数对齐;没有桥接集,跨版本趋势图就是假的。
6. **重标报告**:必须产出"本次降档 X 题 / 淘汰 Y 题 / 补充 Z 题 / 桥接集新旧分差 δ",δ 显著非零时说明整体尺度移动,需在榜单上标注断点。

## 第 2 章 多样性度量

多样性不是"看起来不重复",而是四个层次各自独立达标:**表层词面 → 语义空间 → 任务结构 → 元数据分布**。合成数据最典型的病是前两层过关、后两层塌陷(换了词、换了实体,任务骨架只有五种)。

所有指标按 **门类 × 难度档** 分桶计算,不看全局平均——全局平均会被大门类掩盖小门类的塌缩。

### 2.1 表层多样性

| 指标 | 计算方法 | 阈值 | 依据 | 不通过处置 |
|---|---|---|---|---|
| **distinct-1 / distinct-2** | 桶内所有 prompt 拼接后,unique n-gram 数 / total n-gram 数;中文先分词,英文小写化去标点 | distinct-2 **≥ 0.30**;distinct-1 **≥ 0.08** | [经验] 受桶内样本量影响大,需报 $N$ | 低于阈值 → 该桶整体返工,提高生成种子多样性 |
| **EAD 校正 distinct**(expectation-adjusted) | distinct-n 随 $N$ 增大必然下降,跨桶比较前须按 $N$ 归一 | 比较时统一到 $N=500$ 的子采样 | [经验] 不做这步的跨桶比较无效 | — |
| **self-BLEU** | 桶内随机抽 1000 条,每条以其余为参考算 BLEU-4,取均值 | **≤ 0.25**;> 0.35 判失败 | [需标定] 门类差异大——G7 SQL 题天然句式相似,阈值应单列并实测 | 0.25–0.35 → 定位 top-5% 高相似簇并重写;>0.35 → 整桶返工 |
| **n-gram 重复率** | 4-gram 在桶内出现 ≥2 次的 token 占比 | **≤ 0.20** | [经验] | 提取高频 4-gram 清单人工过;多为模板残留(见第 4 章模板泄漏) |
| **前缀重复** | 按 prompt 前 20 字符聚合,单前缀占比 | 单一前缀 **≤ 3%** | [经验] "请根据以下……"这类开头最容易超标 | 重写开头,不计入语义改动 |
| **长度分布** | prompt / gold 的 token 长度直方图 | 变异系数 CV **≥ 0.5**;不得出现单一长度占比 >10% | [经验] | 长度过于集中 = 模板化的强信号 |

**注意**:表层指标只能证伪不能证真。distinct-2 高而语义塌缩的情况很常见(同一骨架换实体名),所以 2.1 通过 **不构成** 多样性结论,必须叠加 2.2/2.3。

### 2.2 语义多样性

嵌入模型要求:与生成模型、验证模型、被测组合**均不同源**;版本冻结并记录,换模型即需重跑历史基线。

| 指标 | 计算方法 | 阈值 | 依据 | 不通过处置 |
|---|---|---|---|---|
| **有效簇数** | HDBSCAN(不预设 k)或 k-means + silhouette 选 k;在桶内 prompt embedding 上做 | 有效簇数 ≥ **桶内目标 subtype 数 × 2** | [经验] 簇数低于 subtype 数说明生成没覆盖到声明的子类型 | 补生成缺失 subtype |
| **簇内平均距离** | 每簇内样本到簇心的平均余弦距离 | ≥ **0.15** | [需标定] 强依赖嵌入模型尺度,必须先用真实流量算出参考值 | 过低 → 该簇是"一题多改" → 抽样保留,其余删 |
| **最近邻距离分布(1-NN)** | 每条样本到最近邻的余弦距离,看分布而非均值 | **P5 ≥ 0.10**;1-NN 距离 < **0.05** 的样本判近似重复,占比 ≤ **1%** | [需标定] 0.05/0.10 是起步值,需与人工"是否算重复"的标注对齐后回填 | 超标 → 按 1-NN 距离升序做去重(见第 4 章"去重阈值过松") |
| **簇熵 / 归一化熵** | $H=-\sum_c q_c\log q_c$,$q_c$ 为簇 $c$ 的样本占比;归一化 $H/\log C$ | **≥ 0.80** | [经验] | 见下"长尾坍缩" |
| **覆盖半径** | 合成集 embedding 的凸包/最远点采样半径 vs 真实流量的同一量 | 比值 ≥ **0.7** | [需标定] | 语义覆盖面不足,需加新种子主题 |

#### 2.2.1 长尾坍缩的检出(专项)

"长尾坍缩" = 样本名义上分散,实际挤在少数簇里,尾部子类型只有零星几条。**均值类指标(平均距离、平均 distinct)对此完全不敏感**,必须看分布形状。三个可直接算的判据:

| 判据 | 计算 | 判失败条件 | 依据 |
|---|---|---|---|
| **簇规模基尼系数** | 对簇大小向量算 Gini | Gini > **0.60** | [需标定] 与真实流量的 Gini 对比才有意义——真实流量本身也长尾 |
| **Top-k 簇占比** | 最大 5 个簇覆盖的样本占比 | > **50%**(桶内簇数 ≥ 20 时) | [经验] |
| **尾部生存率** | 样本数 ≤ 3 的"微簇"占总簇数比例 | < **20%** 说明尾部没生出来;> **60%** 说明聚类参数不当,先调参再判 | [需标定] |

**正确的对照姿势**:把同一桶的**真实流量**(见第 3 章)做同样的聚类,比较两者的簇规模分布——用 Wasserstein 距离比较两条簇大小曲线。合成集比真实流量**更集中**才是问题;真实流量本身长尾时,强行拉平合成集反而制造分布偏移。

**处置**:不是删大簇,而是**按簇配额重采**——对超配额的大簇下采样至配额,同时把生成预算投到缺失/微簇对应的 subtype 上定向补生成。单纯删大簇会缩小总量且不修根因。

### 2.3 结构多样性(按门类)

表层和语义都过关、结构塌缩,是合成数据最隐蔽的失败。每个门类定义自己的"结构指纹"。

| 门类 | 结构指纹(抽取方式) | 指标与阈值 | 依据 |
|---|---|---|---|
| **G7 代码与SQL** | SQL 走 AST 解析(sqlglot 类),抽取:算子集合(JOIN/GROUP BY/WINDOW/CTE/子查询/聚合/集合运算)、涉及表数、JOIN 数、嵌套深度、谓词数;代码题抽取:控制流深度、调用的标准库模块、返回类型 | 算子类型覆盖 **≥ 10 种**;单一算子组合占比 **≤ 15%**;表数分布须跨 1/2/3/≥4 四档且每档 ≥ 10%;嵌套深度 ≥2 的题占 L3 的 **≥ 60%** | [经验] 与 BIRD 用结构复杂度定义难度的思路一致 [引用] |
| **G9 工具与系统操作** | 从 gold 轨迹抽取:调用步数、工具集合、工具调用序列的 n-gram、是否含分支/重试/回滚、是否含参数缺失或工具缺失场景 | 步数分布跨 1–2 / 3–5 / 6+ 三档,每档 ≥ 15%;单一工具序列(2-gram)占比 **≤ 10%**;含异常分支的题 ≥ **25%**(对齐 BFCL v3 的 Miss Func / Miss Param 类设计)[引用] | [经验] |

### 2.4 元数据均衡:边缘分布 + 联合分布

**只看边缘会漏掉"所有 L3 都是英文"这类结构性偏斜。** 必须同时查联合分布。

维度:`category(G1–S)` × `subtype` × `difficulty(L1/L2/L3)` × `lang(zh/en/其他)` × `role(提问者角色)` × `industry` × `split(dev/test/canary)` × `多轮(是/否)`。

| 检验 | 计算方法 | 阈值 | 依据 | 不通过处置 |
|---|---|---|---|---|
| **边缘偏离** | 各维度实际占比 vs 目标占比的 TVD(总变差距离) | difficulty 对 3:5:2 的 TVD ≤ **0.05**;其余维度 TVD ≤ **0.10** | [经验] difficulty 有硬目标所以更严 | 定向补生成至配额 |
| **成对联合独立性** | 对每一对维度做卡方检验 + **Cramér's V**(效应量,比 p 值更该看,大样本下 p 值必显著) | Cramér's V ≤ **0.15** 视为可接受;> **0.25** 判失败 | [经验/需标定] | 找出贡献最大的单元格,定向补该 (维度A=a, 维度B=b) 组合 |
| **空单元格 / 稀疏单元格** | 列出所有 (category × difficulty × lang) 三元组,统计样本数 | 目标组合中 **0 样本单元格 = 0 个**;样本 < 10 的单元格 ≤ **10%** | [经验] 这是"所有 L3 都是英文"最直接的检出手段——该组合的单元格会直接是 0 | 0 样本单元格必须补齐或显式声明"本期不覆盖"并记入 README |
| **split 平衡** | 每个 (category × difficulty × lang) 单元格内 dev/test/canary 比例 | 各单元格内比例与 30/60/10 的偏离 ≤ **5 个百分点** | [经验] | 重新分层抽样切分——**split 必须按联合分层做**,随机切分在小单元格上必然失衡 |
| **条件难度分布** | 对每个 (category, lang, role, industry) 取值,算其内部 L1:L2:L3 | 每个取值内部的 difficulty TVD ≤ **0.10** | [经验] 这条是"联合分布"检验里最该看的一条 | 定向补生成 |

**报告形式**:每批次输出一张 `category × difficulty × lang` 的三维透视表(展平为二维热力表)+ 一张成对 Cramér's V 矩阵。这两张表比任何单一数字都更能暴露问题,必须进验收报告正文,不能只放附录。

## 第 3 章 与真实流量的分布对齐检验

第 2 章保证"合成集内部足够散",本章保证"散的方向对"——散到真实用户不会问的地方,等于制造了一个没人用的 benchmark。

**前提声明**:对齐的目标**不是** 100% 复刻真实流量。benchmark 需要故意过采样长尾与难例(真实流量里 L3 占比远低于 20%)。所以本章的对齐检验分两类:

- **强对齐维度**(必须贴近真实):输入长度、语言、输入格式、多轮比例、意图分布。
- **弱对齐维度**(允许有意偏离,但偏离必须声明并可复原):门类频次、难度配比。弱对齐维度用**重加权**处理——记录真实流量的门类权重 $w_g$,报分时同时给"均匀分"和"按真实流量加权分"两套数。

### 3.1 对齐维度与统计量

| 维度 | 表示方式 | 统计量 | 阈值 | 依据 |
|---|---|---|---|---|
| **门类频次** | 11 类离散分布 | JS 散度 | 弱对齐:不设硬阈值,但必须产出 $w_g$ 重加权分;JS > **0.20** 时在报告首页标注偏离 | [经验] |
| **意图** | 自建意图标签体系(20–40 个),用同一分类器同时标真实与合成 | JS 散度 | **≤ 0.10** | [需标定] 依赖意图体系粒度,先实测真实流量内部两个时间窗之间的 JS 作为噪声基线,阈值取该基线的 2 倍 |
| **输入长度** | token 数,连续量 | **1-Wasserstein**(对长尾敏感,优于 KL);辅以 KS 检验 | $W_1 / \text{median}(\text{real})$ **≤ 0.25**;KS $D$ ≤ **0.15** | [经验] 用相对 $W_1$ 才能跨门类比较 |
| **语言** | zh / en / 其他 / 混合 | TVD | **≤ 0.05** | [经验] 语言比例错了下游结论全错,所以严 |
| **输入格式** | 纯文本 / 含代码块 / 含表格 / 含日志 / 含 JSON / 含截图描述 / 含链接 | TVD | **≤ 0.10** | [经验] 这是合成数据最容易失真的维度——合成集几乎总是"纯净纯文本"偏多 |
| **多轮比例** | 单轮 / 2–3 轮 / ≥4 轮 | TVD;另比较轮次分布的 $W_1$ | TVD **≤ 0.10** | [经验] |
| **输入"脏度"** | 含错别字/截断/重复粘贴/无关寒暄/口语化 的样本占比(规则+小模型打标) | 绝对差 | 合成集不得低于真实值的 **0.5 倍** | [需标定] 见第 4 章"分布偏移" |

**KL / JS / Wasserstein 选型规则**:

- 离散且两侧都有非零支撑 → **JS**(对称、有界 [0, ln2],便于设阈值)。
- 离散且合成集有真实集没有的取值(零支撑) → **不要用 KL**(会发散),用 JS 或 TVD。
- 连续/序数(长度、轮数、步数) → **Wasserstein-1**,它考虑取值之间的距离,KL/JS 不考虑。
- 所有散度都要报 **bootstrap 95% CI**,并给出"真实流量自身两个时间窗之间"的噪声基线;**没有噪声基线的散度数值不可解读**。

### 3.2 分类器双样本检验(整体对齐,主检验)

边缘分布逐个对齐,联合分布仍可能完全不同(第 2 章同理)。整体检验用 C2ST(classifier two-sample test)。

**做法**:

1. 取真实流量样本 $R$ 与合成样本 $S$,**等量下采样**至 $\min(|R|,|S|)$,标签 1/0。
2. 特征用两套并行跑,结论取更高的 AUC:
   - **特征工程版**:长度、语言、格式 flag、标点/数字/代码占比、轮数、句法深度、词表 OOV 率等。可解释,能直接告诉你"哪个特征在泄露"。
   - **嵌入版**:冻结的第三方嵌入模型(与生成/验证/被测均不同源)+ 逻辑回归或 GBDT。更强,但要防它抓到嵌入模型自身的风格指纹。
3. **5 折交叉验证**,报 out-of-fold AUC 与 95% CI。**必须用 CV AUC,in-sample AUC 恒接近 1,毫无意义。**
4. 按门类分别跑一次,不要只跑全局——全局 AUC 0.6 可能是"G1 完美对齐 + G7 完全跑偏"的平均。

**AUC 阈值与解读**:

| CV AUC(95% CI 下界) | 判定 | 解读与动作 |
|---|---|---|
| **≤ 0.60** | 通过 | 分类器基本分不开;可视为分布接近 |
| 0.60 – 0.70 | 有条件通过 | 存在可察觉差异。**必做**特征重要性/SHAP 归因,定位 top-3 泄露特征并修;修完重跑 |
| 0.70 – 0.85 | 不通过 | 系统性差异。典型归因:长度过于集中、格式过于干净、句式模板化 → 回第 2 章返工生成配置 |
| > 0.85 | 严重不通过 | 合成集与真实流量几乎正交,不能代表线上场景;暂停发布,重设生成种子(改用真实流量做种子,见 3.3) |

补充解读规则:

- **AUC 显著低于 0.5 不是好事**,通常意味着数据泄露/标签错配(例如两侧做了不同的清洗),要查 pipeline。
- AUC 只说"分得开",不说"哪边差"。必须配 SHAP/特征重要性,否则拿到一个 0.72 无从下手。
- **AUC 接近 0.5 也不代表合格**:C2ST 的检验功效受样本量限制,小样本下什么都分不开。所以必须报**功效**:在当前 $n$ 下能检出多大效应量。$n < 500$/侧时 C2ST 结论不可用 [经验]。
- C2ST 分不开只说明**输入分布**像,不保证**难度分布**像——难度另由第 1 章管。

### 3.3 真实流量样本:来源、脱敏、样本量

#### 3.3.1 来源优先级

| 优先级 | 来源 | 覆盖门类 | 说明 |
|---|---|---|---|
| 1 | 线上产品的真实用户请求日志(已获授权、在服务条款覆盖范围内) | G1–G7、G10 | 最优,但受合规约束,且只覆盖已上线场景 |
| 2 | 内部员工真实使用日志(dogfooding) | 全门类 | 合规门槛低,但分布偏技术人群,需在报告标注偏差 |
| 3 | 客服/工单/内部知识库问答记录 | G1、G8、G10 | G8 的最佳来源 |
| 4 | 公开的真人对话数据集(WildChat、LMSYS-Chat-1M 等) | G1、G3、G4、G10 | 域不匹配、语言偏英文,只能作**辅助基线**,不能当唯一真实源 |
| 5 | 人工采编:让一线同事按真实工作写 100–300 条 | G8、G9 | 见 3.4 |

**必须记录来源构成比例**,不同来源分开跑一次 C2ST,避免用来源 1 对齐却宣称覆盖来源 3 的场景。

#### 3.3.2 脱敏要求(前置硬门槛,不脱敏不得进入本流程)

| 项 | 要求 |
|---|---|
| 授权 | 只使用有明确使用授权、在留存期内的日志;逐条记录授权依据与数据来源系统 |
| PII 移除 | 自动识别 + 替换:姓名、手机号、邮箱、身份证/护照号、银行卡、地址、IP、账号 ID、内部工号。用**一致性假名替换**(同一实体在同一会话内替换为同一假名),而非直接删除——直接删会破坏长度和句法分布,污染 3.1/3.2 的检验 |
| 商业敏感 | 客户名、合同金额、未公开产品代号、内部系统名 → 按类型替换为同类占位(保留 token 长度量级) |
| 凭据 | API key / token / 密码 / 私钥 → 正则 + 熵检测双通道扫描,命中即整条丢弃(不是替换) |
| 二次校验 | 脱敏后**人工抽检 ≥ 5%**(或 ≥ 200 条,取大者),漏检率 > **1%** 则脱敏规则返工 [经验] |
| 存储 | 真实流量样本只用于**统计对齐检验**,不进入 benchmark 题库,不参与训练;独立存储、独立权限、设定保留期 |
| 合成侧 | 若真实流量被用作生成种子,产出的合成题必须再过一遍同样的 PII 扫描——种子里的实体会被模型改写后带出 |

#### 3.3.3 样本量下限

| 用途 | 每门类最小样本量 | 依据 |
|---|---|---|
| 边缘分布(离散,如语言/格式) | **300** | [经验] 估计一个占比 10% 的类别,95% CI 半宽约 ±0.034 |
| 边缘分布(连续,如长度的 $W_1$) | **500** | [经验] $W_1$ 的 bootstrap CI 在 500 以下过宽 |
| **C2ST** | **每侧 ≥ 500**,推荐 **1000** | [经验] 见 3.2 功效说明;低于 500 结论不可用 |
| 意图分布(20–40 类) | **1000** | [经验] 类别多,尾部类别需要够多样本 |

全局(不分门类)最低 **3000 条**真实样本;某门类不足 300 条时,**明确标注该门类未做对齐检验**,不得用全局结论覆盖。

### 3.4 诚实说明:G8 / G9 本就缺真实流量

这是本章最大的短板,不遮掩。

**为什么缺**:G8 故障诊断的真实场景发生在运维/SRE 的排障过程里,大多在工单系统、监控平台和 IM 里,不以"向 LLM 提问"的形式存在;G9 工具与系统操作依赖具体的工具集与权限环境,线上尚无成规模的真实 agent 调用日志。对这两类,3.1/3.2 的检验**没有合格的对照侧**。

**替代方案(按可信度排序,不是等价物)**:

| 方案 | 做法 | 能替代什么 | 不能替代什么 |
|---|---|---|---|
| **A. 代理流量** | 用工单系统/告警记录/变更单/runbook 执行日志作为 G8 的代理真实源;用已有自动化脚本、CLI 历史、API 调用日志作为 G9 的代理源 | 可做输入长度、格式、故障层分布、工具组合分布的对齐 | 不能做意图与多轮比例对齐——原始记录不是对话 |
| **B. 专家采编** | 一线 SRE / 运维 / 工程同事按真实经历写 **≥ 150 条/门类**,要求"必须来自你处理过的真实事件",并记录事件时间与系统 | 提供一个小但真实的对照侧,足够做边缘分布对齐 | 样本量不足以跑 C2ST(< 500);只能做 3.1 不能做 3.2 |
| **C. 结构先验** | 放弃与流量对齐,改为与**领域结构先验**对齐:故障层占比参照历史事故统计;工具组合参照实际工具目录的调用频次统计 | 保证不生成"现实中不存在的故障类型/工具组合" | 完全不能替代分布对齐,只是下限约束 |
| **D. 事后校准** | 上线后收集真实 G8/G9 请求,**每季度**回补对照侧并重跑本章检验 | 长期正解 | 首个版本无解 |

**首版必须在 README 与验收报告里写明**:

> G8、G9 未通过第 3 章的分布对齐检验(缺真实流量对照侧),当前仅完成方案 B + C 的替代校验。这两个门类的分数**不代表线上真实场景表现**,仅可用于模型间横向比较,不可用于绝对能力宣称。

这条声明不允许在后续版本里被静默删除——只能在方案 D 有实际数据后,替换为带日期的对齐结果。

### 3.5 对齐检验判定

| 等级 | 条件 | 动作 |
|---|---|---|
| 通过 | 所有强对齐维度达标,且各门类 C2ST AUC 下界 ≤ 0.60 | 发布 |
| 有条件通过 | 个别门类 AUC 0.60–0.70,已完成归因且列出修复计划 | 发布并在报告标注该门类偏差方向 |

## 第 4 章 合成数据失败模式清单

严重度定义:**S1** = 使分数失真、必须整批阻断发布;**S2** = 局部失真,可定点修复后发布;**S3** = 质量瑕疵,记录并下周期修。
每条的"检出手段"都是可直接排进流水线的自动检查(除非明确标注人工),不是靠眼看。

### 4.1 失败模式总表

| # | 失败模式 | 表现 | 成因 | 检出手段(可执行) | 严重度 | 处置 |
|---|---|---|---|---|---|---|
| F1 | **表面变体**(换名换数,结构同构) | 一千道题只有 30 个骨架;模型学会骨架后全对 | 生成时以少量种子题做"改写扩增";temperature 低;few-shot 示例固定 | ① 结构指纹哈希:按 2.3 抽取门类结构指纹(G7 走 SQL AST 归一化后哈希,G9 走工具序列 n-gram,G1 走「问题类型+答案类型+关系谓词」三元组),统计**唯一指纹数 / 样本数**,< **0.30** 判失败 [需标定];② 实体遮蔽重测:把所有具名实体/数字替换为占位符后再算 self-BLEU,若遮蔽后 self-BLEU 相比遮蔽前**上升 > 0.15**,说明多样性全靠换名 [经验];③ 同骨架题的基线通过率相关系数 > 0.9 | **S1** | 整批返工:提高种子题数量、轮换 few-shot、引入结构约束采样(先采结构骨架再填内容) |
| F2 | **模板泄漏**(残留生成指令) | prompt/gold 里出现「请生成一道…」「以下是L3难度题目」「作为出题人」「[插入具体数值]」「Sure, here is」 | 生成模型把 meta-prompt 抄进输出;JSON 解析边界处理不严 | ① 正则黑名单扫描(中英双语,覆盖:生成/出题/难度档位名/占位符括号/markdown 代码围栏残留/助手开场白),**命中即拦截,零容忍**;② 难度标签词 `L1|L2|L3|easy|medium|hard|简单|困难` 出现在题面中即告警;③ 每批次抽 100 条人工过一遍,新发现的模式立刻回写黑名单 | **S1** | 自动拦截并丢弃;黑名单必须版本化并在每批次前更新 |
| F3 | **gold 泄漏**(答案出现在 prompt 里) | 题面里已含答案;或含唯一指向答案的强线索 | 反向生成天生高危——先造 gold 再倒推 prompt,倒推时容易把 gold 的措辞带进 prompt | ① **字面包含检查**:gold 归一化(去标点/大小写/空白)后作为子串在 prompt 中检索,命中即拦截;数值型 gold 检查数值是否出现在 prompt(排除题面必需的输入数据);② **重叠度**:gold 与 prompt 的最长公共子串长度 / gold 长度 > **0.6** 告警 [经验];③ **空模型探针(最有效)**:用一个**弱模型**、**零上下文**、**不给任何工具/文档**直接答题,若通过率 > **0.30** 说明题面泄漏或题目不需要真能力 [需标定];④ **遮蔽重测**:把 prompt 中与 gold 重叠的片段遮蔽后,强模型通过率若**不降**,说明该片段本不是线索——反向推断原本泄漏的位置 | **S1** | 泄漏题重写 prompt(不改 gold);同批泄漏率 > 5% 则倒推流程返工 |
| F4 | **self-preference 自指偏置** | 生成模型自家系列在该题集上分数系统性偏高 | 生成/验证模型与被测同源;judge 偏好自己的措辞风格 | ① **同源 vs 异源分差**:把被测组合按"是否与生成模型同源"分组,比较两组在合成集 vs 公开锚点集上的分差 $\Delta$,$|\Delta| > $ **0.05** 显著即判偏置 [需标定];② **交叉生成对照**:同一 subtype 用 ≥3 个不同源模型各生成一批,看被测排名是否随生成方来源而变——**排名的 Kendall τ < 0.85 即判失败** [经验];③ judge 侧做 **swap test**:调换答案顺序/匿名化措辞后重判,判决翻转率 > **10%** 告警 | **S1** | 强制多模型交叉生成后做来源均衡;报分时按生成来源分层报,不只报总分 |
| F5 | **难度塌缩** | 标称 L3,实测基线通过率 > 0.8;三档通过率无阶梯 | 生成模型不理解"难",只是把题面写长/加术语;反向生成时 gold 过于直白 | ① 第 1 章的锚点映射 + 档均通过率越界检查(T1/T2);② **档间分离度**:$\bar p_{L1} - \bar p_{L2}$ 与 $\bar p_{L2} - \bar p_{L3}$ 均需 ≥ **0.15** [经验];③ **难度-长度混淆检查**:难度标签与题面长度的相关系数 > **0.5** 说明"长=难"的伪难度 [经验] | **S1** | 按 1.4.2 降档 + 从 frontier 池补 L3;生成 prompt 改为"先定难点类型再造题" |
| F6 | **分布偏移**(全是理想化干净输入) | 无错别字、无截断、无口语、无冗余粘贴、格式永远规范 | 生成模型默认输出规范文本 | ① 第 3 章的"输入脏度"维度:错别字率、口语标记词频、非标准格式占比,与真实流量比,合成侧低于真实侧 **0.5 倍**即判失败;② C2ST 的 SHAP 归因中若"格式/标点/OOV 类特征"进 top-3,即为本模式;③ 格式分布 TVD > 0.10 | **S2** | 定向注入真实噪声:按真实流量的噪声类型分布做可控扰动(**扰动后必须复核 gold 仍成立**),或直接用真实流量做 prompt 种子 |
| F7 | **长度偏置**(judge 偏爱长答案) | rubric 门类(G4/G5/G10)里长答案系统性高分;模型学会灌水 | LLM judge 的已知偏好 | ① **长度-得分相关**:Spearman $\rho$(答案 token 数, judge 分),$\rho > $ **0.3** 即判存在偏置 [经验];② **控制实验**:对同一答案做「压缩 30% 但保留全部 rubric 要点」的改写,重判后分数下降 > **0.5 分**(10 分制)即确认偏置 [需标定];③ 分桶检查:按答案长度四分位分组,比较各组平均分与**人工分**的偏差 | **S1**(对 G4/G5/G10)/ S3(其余) | rubric 改为**逐条二值判定**(满足/不满足)后加总,而非整体打分;judge prompt 显式声明"长度不计分";必要时按长度分层归一化 |

| F9 | **多解未记**(gold 只记一条,其他正确解判错) | 模型给了正确的另一种写法却判错;该题点二列相关为**负** | gold 单一化;checker 用字符串精确匹配 | ① **负区分度筛查**(最高效):第 1 章 1.3.2 中 $r_{pb} < 0$ 的题 100% 人工复核,多解未记是其首要成因;② **失败答案聚类**:把所有被判错的答案做聚类,若某簇内 ≥ **3** 个不同模型给出高度一致的答案,该簇极可能是未记录的正确解,强制人工裁定 [经验];③ G7:对判错的 SQL 用**执行结果等价**(同库跑出同结果集)重判,而非字符串比对;G6:数值答案加容差(相对误差 **1e-3**,需按题标注);G9:工具调用用**终态等价**判定而非序列精确匹配 | **S1** | gold 升级为**答案集合 + 等价判定函数**;checker 从精确匹配改为语义/执行等价;已受影响的历史分数需重算 |
| F10 | **语言不自然**(翻译腔) | 中文题面是英文句式直译;「进行一个…的操作」「基于以上所述」密集 | 生成模型以英文思维产出后翻译;few-shot 全是英文 | ① **困惑度对照**:用一个**中文原生语料训练**的第三方小模型算题面 PPL,与真实中文流量的 PPL 分布比,合成侧 P50 高出 **1.3 倍**即告警 [需标定];② **翻译腔标记词表**:被动式密度、"的"字串长度、四字格缺失率、英式长定语占比,做规则打分;③ **回译一致性**:中→英→中回译后与原文的编辑距离**异常小**(< 0.15)说明原文本就是英文直译 [经验];④ 每批人工抽检 50 条,由母语者二值判"是否像人写的",不自然率 > **10%** 判失败 | **S2** | 中文题由中文优势模型重写;few-shot 换成真实中文流量样本;**禁止用"翻译英文题"的方式补中文配额** |
| F11 | **验证者与生成者同源 → 共谋通过** | 验证通过率异常高(> 95%);验证模型系统性放过生成模型的特定错误类型 | 验证模型与生成模型同源/同家族/同数据 | ① **同源审计(前置)**:维护模型家族谱系表,流水线在运行前硬校验「生成模型家族 ≠ 验证模型家族 ≠ 被测组合家族」,不满足直接拒绝执行——这是配置检查,不是事后统计;② **第三验证者交叉**:对每批随机抽 **10%** 用第 3 个独立来源的模型复验,两验证者的**一致率 < 85%** 说明至少一方有系统偏差 [经验];③ **注入式检验(最硬)**:向验证队列**故意注入已知坏题**(错 gold / 泄漏 / 虚构),各类 **各 20 条**,验证器的**漏检率 > 10% 即判验证环节失效** [经验];④ 验证通过率本身做监控:某生成模型的通过率显著高于其他生成模型(> 10 个百分点)即告警 | **S1** | 立即更换验证模型;该验证者已通过的批次全部重验;注入式检验固化为每批次必跑的流水线步骤 |
| F12 | **近似去重阈值过松** | 去重后仍有大量"几乎一样"的题;train/test 之间存在近邻对 | 阈值拍脑袋定;只做精确去重或低维 MinHash | ① **双通道去重**:字面通道 MinHash-LSH(shingle=5,Jaccard 阈值 **0.7** [经验]) + 语义通道 embedding 1-NN 余弦(阈值 **需标定**,方法见下);② **阈值标定法**:人工标注 **300 对**跨相似度区间的样本对(是否算重复),画 precision-recall,取 **precision ≥ 0.95** 处的阈值作为删除线,precision 0.8 处作为"送人工"线——**不接受未经标注直接用 0.9 之类的默认值**;③ **跨 split 泄漏专查**:test/canary 中的每条,对 dev 做 1-NN 检索,相似度超删除线即视为泄漏,**必须为 0 条**;④ 去重后复跑 2.2 的 1-NN 距离 P5,仍 < 0.10 说明阈值仍松 | **S1**(跨 split 泄漏)/ S2(集内冗余) | 跨 split 近邻:从 test 侧删除(保 dev);集内冗余:同簇保留 1 条 + 按结构指纹差异保留代表,其余删除并补生成 |

### 4.2 三条容易被忽略的交叉检查

| 检查 | 为什么单独列 | 做法 |
|---|---|---|
| **空模型探针** | 一次性同时暴露 F3(gold 泄漏)、F5(难度塌缩)、部分 F1 | 弱模型 + 零上下文 + 无工具直接答全集,按门类报通过率;任何门类 > 0.30 即回查 [需标定] |
| **注入式坏题检验** | 唯一能证明"验证环节真的在工作"的手段(F11);其余检查都只验数据,不验验证器 | 每批次注入四类已知坏题各 20 条(错 gold / 答案泄漏 / 事实虚构 / 模板残留),统计验证器漏检率;漏检率进验收报告正文 |
| **负区分度复核** | 同时是 F9、F3、checker bug 的最高效入口,成本极低 | $r_{pb} < 0$ 的题 100% 人工过,每题记录归因类别并回写到本表统计 |
